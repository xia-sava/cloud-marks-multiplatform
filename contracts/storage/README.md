# contracts/storage

S3 上の形式（`docs/storage-format.md`）の見本を置く。

`apps/cm` の `shared` のテストが読み、読み書きの実装がこの見本どおりの形を扱えることを確かめる。

形式を変えるときは、見本と実装を同じ変更で直す。

## `example/`

プレフィックスの下のキーの並びをそのまま写したもの。S3 では gzip で圧縮して `.jsonl.gz` の名前で置くが、
見本は読みやすさのため圧縮せず `.jsonl` の名前で置く。

```text
example/
├─ manifest.jsonl
└─ folders/<フォルダの ID>/<ファイルの ID>.jsonl
```

含めている形：

- ルートフォルダ（名前が空）と、ルートフォルダが直接持つ項目（単体で追加したブックマーク）
- 項目を持たず、子のフォルダだけを持つフォルダ（`子のフォルダだけ`）
- 子のフォルダと項目の両方を持つフォルダ（`子と項目の両方`）
- 項目の無いフォルダ（`空のフォルダ`、`A/B`）。`items` が null で、`count` が 0
- 名前に `/` を含むフォルダ（`A/B`）
- 複数のタブから追加したフォルダ（`2026-11-16 21:30:15`）。追加した項目は `added` を持つ
- 同じ URL を持つ複数の項目、空のタイトル、`about:` の URL

ID は読みやすさのため連番に近い値にしている。実際の ID は乱数の UUID になる。
フォルダの名前は例であり、追加したフォルダの名前の付け方を定めるものではない。
