# Native Messaging の取り決め

ブラウザ拡張（`apps/extension`）とデスクトップ側のホストのあいだの取り決め。拡張は、選択したタブをホストへ渡して
S3 に追加させる。また、デスクトップのアプリからのコマンドを、ホストを通じて受け取ってタブを開く（「ブラウザで開く」）。
拡張は S3 にアクセスせず、保存形式のロジックも持たない。ホストが S3 へ書く。

## 経路

- ホストの名前は、配布版が `to.sava.cloudmarksmultiplatform`、開発版が `to.sava.cloudmarksmultiplatform.dev`
  （下の「配布版と開発版」）
- 拡張は 1 回の追加などごとに `runtime.sendNativeMessage` でメッセージを 1 つ送る。ブラウザがホストを起動する。
  ホストはメッセージを 1 つ読み、応答を 1 つ返して終わる。デスクトップのアプリが起動していなくても追加できる
- メッセージは、4 バイトの長さと、それに続く UTF-8 の JSON。長さはネイティブのバイト順で、Windows ではリトルエンディアン
- ホストの応答は 1 MB を超えない（Chrome の上限）
- ホストはデスクトップのアプリと同じ配布物に入り、同じ PC のアプリの設定（S3 の接続先と認証情報）を使う
- ホストは `docs/operations.md` の操作を、`docs/storage-format.md` の書き込みの手順で S3 へ書く。マニフェストのヘッダーの `updatedBy` は `"host"`
- ホストはローカルキャッシュを読みも書きもせず、毎回 S3 から読む。同じ PC のアプリとローカルキャッシュを取り合わないため
- ホストは標準出力に応答のほかは何も書かない。ログはアプリと同じディレクトリのファイルに書く
- ホストは、書き込みが成功したとき、または結果が不明のとき、アプリのデータを置くディレクトリの `state\storage-changed` を
  書き換える。起動しているデスクトップのアプリはこのファイルを見張り、書き換わったら S3 から読み直す。中身は使わない。
  アプリが読み直しや書き込みの最中のとき、設定の画面か以前の状態に戻す画面を開いているときは読み直さない（読み直すボタンで読み直す）

## ホストの登録

インストーラが、ホストを登録する JSON を置き、そのパスをレジストリに登録する。登録するのは配布版のホストで、
管理者権限は要らない（`HKCU` に書く）。

| ブラウザ | レジストリのキー | 受け付ける拡張 |
|---|---|---|
| Chrome | `HKCU\Software\Google\Chrome\NativeMessagingHosts\<ホストの名前>` | `allowed_origins` に `chrome-extension://<Chrome の拡張の ID>/` |
| Firefox | `HKCU\Software\Mozilla\NativeMessagingHosts\<ホストの名前>` | `allowed_extensions` に `<Firefox の拡張の ID>` |

- 各キーの既定の値（名前の無い値）が、ホストを登録する JSON のパス。インストール先（`%LOCALAPPDATA%\Programs\CloudMarks`）を
  `<インストール先>` とすると、Chrome は `<インストール先>\cloud-marks-host.chrome.json`、Firefox は `<インストール先>\cloud-marks-host.firefox.json`。
  インストーラは、インストール先を利用者に選ばせない
- JSON の `path`（ホストを起動するファイル）は、JSON と同じ場所の `cloud-marks-host.exe` を指す相対パス
  （`cloud-marks-host.exe`）。Chrome と Firefox の両方で、JSON のある場所からの相対として解決される
- `cloud-marks-host.exe` はデスクトップのアプリのランチャー（`CloudMarks.exe`）のコピーで、`app\cloud-marks-host.cfg` が
  起動するクラスをホストのものにする
- 更新のインストールは、キーの値を同じ内容で書き直す。アンインストールは 2 つのキーを（キーごと）消す。
  開発版のホストのキーには触れない
- アンインストールしても、アプリのデータを置くディレクトリ（`%LOCALAPPDATA%\CloudMarks`）の設定、認証情報、キャッシュ、ログは消えない。
  アンインストールが消すのはインストール先のファイルだけ

### 配布版と開発版

配布版と開発版は、同じ PC とブラウザに並べて入れられるよう、ホストの名前、拡張の ID、呼び出しの URL のホスト、
アプリのデータを置くディレクトリを分ける。名前の一覧は `contracts/native-messaging/identities.json` にある。

| | 配布版 | 開発版 |
|---|---|---|
| ホストの名前 | `to.sava.cloudmarksmultiplatform` | `to.sava.cloudmarksmultiplatform.dev` |
| Chrome の拡張の ID | `laeogpkfjeccgfkedalbkcbenakkefpl` | `bnnjmdaaeahhkjopgaeacdpajlfbodca` |
| Firefox の拡張の ID | `cloud-marks-multiplatform@sava.to` | `cloud-marks-multiplatform-dev@sava.to` |
| 呼び出しの URL のホスト | `cmm.invalid` | `cmm-dev.invalid` |
| 拡張の名前 | `Cloud Marks` | `Cloud Marks (dev)` |
| アプリのデータを置くディレクトリ | `%LOCALAPPDATA%\CloudMarks` | `%LOCALAPPDATA%\CloudMarks-dev` |

- 配布版のホストは配布版の拡張だけを、開発版のホストは開発版の拡張だけを受け付ける。`allowed_origins` と
  `allowed_extensions` には、配布版のホストなら配布版の、開発版のホストなら開発版の ID を 1 つだけ書く
- Chrome の拡張の ID は、拡張の `manifest.json` の `key`（公開鍵）から決まる。配布版と開発版の `key` も `identities.json` にある
- デスクトップのアプリは、配布物のランチャー（`CloudMarks.exe`）から起動したときに配布版になり、`:desktopApp:run` などで
  ビルドしたクラスから直に起動したときは開発版になる。ホストも、配布物から起動したときに配布版になり、
  `writeDevNativeMessagingHost` が書き出したホストは開発版として動く
- インストーラが登録するのは配布版のホスト。開発版のホストを登録する手順は `apps/cm/README.md` の「開発版のホスト」にある

## 拡張から送るもの

メッセージは `type` で 4 種類に分かれる。どれも `protocol` と `type` を持つ。`protocol` は取り決めのバージョンで、整数の `1`。

| `type` | 内容 |
|---|---|
| `"addFolder"` | フォルダを追加 |
| `"addBookmarks"` | ブックマークを追加 |
| `"extensionPresent"` | このブラウザに拡張が入っていることを知らせる（「ブラウザで開く」） |
| `"takeCommand"` | アプリからのコマンドを受け取る（「ブラウザで開く」） |

ホストは、`protocol` が知らないバージョンのとき、`type` が知らない値のとき、欄が欠けているときや下の決まりに合わないときは、
何も書かずに `invalidRequest` を返す。表に無い欄は無視する。

### 追加

```json
{"protocol":1,"type":"addFolder","name":"2026-11-16 21:30:15","tabs":[{"url":"https://example.com/","title":"Example"}]}
```

| 欄 | 型 | 内容 |
|---|---|---|
| `protocol` | 整数 | 取り決めのバージョン。`1` |
| `type` | 文字列 | `"addFolder"`（フォルダを追加）か `"addBookmarks"`（ブックマークを追加） |
| `name` | 文字列 | `addFolder` のときだけ持つ。フォルダの名前。空でない |
| `tabs` | 配列 | タブの並び。1 つ以上 |
| `tabs[].url` | 文字列 | 空でない |
| `tabs[].title` | 文字列 | 空でもよい |

- `addFolder` は `docs/operations.md` の「フォルダとして追加」、`addBookmarks` は「ブックマークとして追加」になる
- 項目とフォルダの ID はホストが振る。追加した日時もホストが入れる

### 拡張が入っていることの知らせ

```json
{"protocol":1,"type":"extensionPresent"}
```

- 拡張は、インストールされたときと更新されたとき（`runtime.onInstalled`）、ブラウザが起動したとき（`runtime.onStartup`）に送る
- ホストは、自分を起動したプロセスを親へさかのぼってブラウザの実行ファイルを見つけ、そのパスをアプリのデータを置く
  ディレクトリの `state\browsers-with-extension.json` に書き足す。デスクトップのアプリは、ここに載っているブラウザだけを、
  2 つ以上の項目を開くときに選べるようにする
- ホストはそのまま `{"ok":true}` を返す。実行ファイルを見つけられない、記録を書けないときもログに書くだけで、`{"ok":true}` を返す

`browsers-with-extension.json` の形（アプリとホストのあいだだけで使う）：

```json
{"browsers":["c:\\program files\\google\\chrome\\application\\chrome.exe"]}
```

- `browsers` は実行ファイルの絶対パスの並び。比べやすいように小文字にそろえ、同じものは 1 つだけ持つ
- 拡張を外しても記録は消えない

### コマンドを受け取る

```json
{"protocol":1,"type":"takeCommand","token":"0123456789abcdef0123456789abcdef"}
```

| 欄 | 型 | 内容 |
|---|---|---|
| `token` | 文字列 | コマンドのトークン。小文字の 16 進で 32 文字。これに合わなければ `invalidRequest` |

- ホストは、アプリのデータを置くディレクトリの `commands\<token>.json` を読んで消し、その中身を `command` として返す
  （下の「ホストが返すもの」）
- ファイルが無いとき（知らないトークン、受け取り済み）は、`command` を `null` にして返す
- 中身が下の「コマンドの形」に合わないとき、応答が 1 MB を超えるときも、`command` を `null` にして返し、ログに書く。
  このときはファイルを消さない。アプリが、10 秒たってもファイルが残っていれば知らせるので、利用者が気づける

## ホストが返すもの

成功：

```json
{"ok":true}
```

`takeCommand` の成功：

```json
{"ok":true,"command":{"type":"openTabs","tabs":[{"url":"https://example.com/","title":"Example"}],"loadAtOnce":3,"loadAhead":20}}
```

コマンドが無いときは `{"ok":true,"command":null}`。

失敗：

```json
{"ok":false,"error":{"code":"storageUnavailable","message":"S3 に接続できませんでした。"}}
```

| 欄 | 型 | 内容 |
|---|---|---|
| `ok` | 真偽値 | 追加では S3 に書けたか。そのほかでは要求を受け付けたか |
| `command` | オブジェクトか `null` | `takeCommand` の成功のときだけ持つ。下の「コマンドの形」 |
| `error.code` | 文字列 | 失敗の種類。下の表 |
| `error.message` | 文字列 | 画面に出す文。ホストが作り、拡張はそのまま出す |

| `code` | 内容 |
|---|---|
| `notConfigured` | アプリで S3 の接続先や認証情報が設定されていない、またはその設定を読めない |
| `storageUnavailable` | S3 につながらない、または権限が無い |
| `updateRequired` | データの形式のバージョンがホストより新しく、書けない（`docs/storage-format.md` の「形式のバージョン」） |
| `dataBroken` | S3 上のマニフェストか項目ファイルが壊れている、マニフェストがまだ無い、またはマニフェストが消されている |
| `busy` | 書き込みの再送や再適用が、回数の上限を超えた |
| `unconfirmed` | マニフェストを書き換えたかどうかを確かめられなかった。書き換えが済んでいることもある |
| `invalidRequest` | 送られたメッセージが、この取り決めに合わない |
| `internal` | そのほかの失敗 |

拡張は、知らない `code` を受けても `message` を出す。

ホストは、マニフェストを書き換えたかどうかを確かめられないとき、同じ操作（同じ ID）で書き込みをやり直す。届いていた分は
適用済みになり、二重にはならない。やり直しても確かめられなければ `unconfirmed` を返す。利用者がもう一度追加すると、
ホストが新しい ID を振るため二重になりうる。`message` はそのことを伝える。

## 拡張の振る舞い

ツールバーのボタンを押すと、ポップアップを出す。

- 対象は、いまのウィンドウで選択しているタブ（`tabs.query({highlighted: true, currentWindow: true})`）。URL の無いタブは除く
- 動作はラジオボタンで「フォルダを追加」「ブックマークを追加」から選ぶ。既定は、タブが 1 つなら「ブックマークを追加」、
  2 つ以上なら「フォルダを追加」
- 名前の欄を 1 つ持つ
  - 「フォルダを追加」：フォルダの名前。既定は、いまのローカル時刻で `YYYY-MM-DD HH:mm:ss`。空なら OK を押せない
  - 「ブックマークを追加」でタブが 1 つ：項目のタイトル。既定はタブのタイトル。送るときは、この値をそのタブの `title` にする
  - 「ブックマークを追加」でタブが 2 つ以上：入力できない。各タブのタイトルをそのまま使う
- ボタンは `OK` と `キャンセル`。Enter で OK、Esc でキャンセル
- OK で送り、成功したらポップアップを閉じる。失敗したら閉じずに `error.message` を出す。ホストが登録されていないとき、
  ホストが応答を返さずに終わったとき、応答がこの取り決めに合わないときは、拡張が自分の文を出す
- 送るのはバックグラウンド。ポップアップは OK でバックグラウンドへ要求を渡し、結果を待つ。ポップアップを閉じても書き込みは
  途中で止まらない
- 結果が出る前にポップアップが閉じていて、失敗だったときは、ツールバーのボタンに `!` を付け、ボタンの説明を失敗を伝える文に
  変える。次にポップアップを開いたとき、前回の失敗とその `error.message` を出し、ボタンの `!` を外して説明を元に戻す

## アプリからのコマンド（ブラウザで開く）

Native Messaging は、拡張の側からしかやり取りを始められない。デスクトップのアプリから拡張へのコマンドは、ファイルと URL で受け渡す。

1. アプリが、コマンドをアプリのデータを置くディレクトリの `commands\<token>.json` に書く。`token` は使い捨ての乱数
   （小文字の 16 進で 32 文字）
2. アプリが、選んだブラウザを呼び出しの URL `https://<呼び出しの URL のホスト>/knock?token=<token>` で起動する。
   配布版は `https://cmm.invalid/knock?token=<token>`、開発版は `https://cmm-dev.invalid/knock?token=<token>`
3. 拡張がその URL を開いたタブを見つけて、`takeCommand` でコマンドを受け取り、そのタブを閉じる
4. 拡張がコマンドのとおりにタブを開く

- `.invalid` は名前が決して引けない予約のドメインなので、拡張が入っていないブラウザで開いても、どのサーバーにも届かない
- 配布版の拡張は配布版の、開発版の拡張は開発版の呼び出しの URL を開いたタブだけを見つける。配布版と開発版の拡張を
  同じブラウザに入れても、配布版のアプリのコマンドは配布版の拡張が、開発版のアプリのコマンドは開発版の拡張が受け取る
- アプリはブラウザを起動してから 10 秒たってもファイルが残っていれば、拡張に届かなかったかもしれないことを利用者に知らせる。
  ファイルは消さない。ブラウザの起動が遅いだけなら、あとで届く
- アプリは新しいコマンドを書くとき、1 時間より古いコマンドのファイルを消す
- 項目が 1 つだけのときは、コマンドを使わず、URL をブラウザの起動の引数にして渡す。引数として 1 つに保てない文字
  （空白や引用符など）はパーセントエンコードし、スキームで始まらない URL は渡さない

### コマンドの形

```json
{"type":"openTabs","tabs":[{"url":"https://example.com/","title":"Example"}],"loadAtOnce":3,"loadAhead":20}
```

| 欄 | 型 | 内容 |
|---|---|---|
| `type` | 文字列 | `"openTabs"`（タブを開く） |
| `tabs` | 配列 | 開く順のタブの並び。1 つ以上。`url` は空でない文字列、`title` は文字列（空でもよい） |
| `loadAtOnce` | 整数 | 同時に読み込むタブの数。1 以上 2147483647 以下 |
| `loadAhead` | 整数 | 先頭から順に読み込むタブの数。これより後ろのタブは、表示したときに読み込む。`0` ならすべてのタブを順に読み込む。0 以上 2147483647 以下 |

- コマンドのファイルの中身はこの JSON そのもの。ホストは中身を検証し、合っていれば上の表の欄を返す（表に無い欄は落とす）

### 拡張がタブを開く

- 呼び出しの URL を開いたタブを見つけたら、そのタブのウィンドウの、そのタブのすぐ後ろに、コマンドのタブを順に並べ、
  先頭のタブを表示する。呼び出しの URL のタブは閉じる
- ブラウザが起動していなかったとき、拡張が動き出す前に呼び出しの URL が開いていることがある。拡張は起動したとき
  （`runtime.onStartup`）に、開いているタブから呼び出しの URL を探す
- `command` が `null` なら、呼び出しの URL のタブを閉じるだけにする。トークンの形が合わなければ、ホストへ送らずに閉じる
- タブはまず拡張の仮のページで作り、本来のタイトルを出す。仮のページは、本来の URL とタイトルを自分の URL に持つ
- 仮のページは、表示されたときに自分で本来の URL へ移る。ブラウザを起動し直して復元された仮のページも同じように動く
- 拡張は、先頭から `loadAhead` 本（`0` ならすべて）のタブに、`loadAtOnce` 本ずつ本来の URL を読み込ませる。1 本の読み込みが
  終わるか、一定の時間がたつか、そのタブが閉じられるか、仮のページが自分で移ったら、次へ進む
- それより後ろのタブは、拡張は読み込ませず、表示されたときに移る
- `http:` と `https:` でない URL（`file:` やブラウザの内部のページなど）は、ブラウザが移るのを拒むことがある。そのときタブは
  仮のページのまま残り、タイトルと URL を出す
- ホストからコマンドを受け取れなかったとき（送信の失敗、失敗の応答）も、呼び出しの URL のタブを閉じる。アプリが 10 秒後に
  知らせる
